Besluiten en citaten: `docs/concept/IDEEEN.md` → "Glitch → bug → virus".

Doel van de test: kan een lijf van codesymbolen een Gen 3-sprite met volume worden?
Eigen invulling Claude (niet door Jordi gezegd, schrappen bij twijfel): de symbolen { } [ ] ; als lichaamsdelen; versie B met een insectenbouwplan; tweede type weggelaten (open).

## r1A (nieuw gesprek, zonder bijlage): vrij wezen van symbolen
```
Design an original Pokemon. Type: Bug. It is the middle stage of a three-stage line: glitch, then bug, then virus. This Pokemon is a "bug" in the computer sense: a programming error that has come alive. It is NOT a normal insect. It is a small creature whose body is built from a few programming symbols.

Body: its body parts ARE large programming symbols, drawn as solid 3D objects with volume, shading and a dark outline, like sculpted solid shapes, NOT flat text. For example: a pair of curly braces { } forms its pincers or jaws, square brackets [ ] form its legs, a semicolon or dots form its eyes. Use only a few big symbols (3 or 4 kinds at most), so the silhouette stays clear and readable. It has a face with two clear eyes and an expression; it looks like a living creature, not an icon or a logo.

Style: official Gen 3 front sprite (Ruby/Sapphire/Emerald style), 64x64, max 16 colors, dark outline, clean shapes with shading, facing 3/4 to the left, compact composition. White background, no ground, no shadow, no effects, no glow.

AVOID: readable text or words, lines of code, letters, screens or computers, robots, glowing, green-on-black Matrix look, pixel noise or blurry static, a realistic insect, Porygon, Unown, MissingNo.
```

## r1B (nieuw gesprek, zonder bijlage): insectenbouwplan van symbolen
```
Design an original Pokemon. Type: Bug. It is the middle stage of a three-stage line: glitch, then bug, then virus. This Pokemon is a "bug" in the computer sense: a programming error that has come alive. It is a conceptual bug, NOT a typical insect: it only borrows the basic body plan of a small beetle (head, body, six short legs), but every body part IS a programming symbol.

Body: the parts are large programming symbols, drawn as solid 3D objects with volume, shading and a dark outline, like sculpted solid shapes, NOT flat text. For example: the jaws are a pair of curly braces { }, the legs are square brackets [ ] or angle brackets < >, the eyes are dots of a semicolon. Use only a few big symbols (3 or 4 kinds at most), so the silhouette stays clear and readable. It has a face with two clear eyes and an expression; it looks like a living creature, not an icon or a logo.

Style: official Gen 3 front sprite (Ruby/Sapphire/Emerald style), 64x64, max 16 colors, dark outline, clean shapes with shading, facing 3/4 to the left, compact composition with the legs close to the body. White background, no ground, no shadow, no effects, no glow.

AVOID: readable text or words, lines of code, letters, screens or computers, robots, glowing, green-on-black Matrix look, pixel noise or blurry static, a realistic beetle, Porygon, Unown, MissingNo.
```

Design an original Pokemon. Type: Electric/Bug. It is the middle stage of a three-stage line: glitch, then bug, then virus. It is a purely digital creature: a glitch that has become sentient.
